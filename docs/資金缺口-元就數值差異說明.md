# 資金缺口計算差異說明（A公司）

## 已修正的邏輯（server.js）

### 1. 結算記錄優先「帳戶完全符合」

**問題**：若同一公司有多個銀行帳戶，且同時存在「公司級期初」（結算的 account_name / account_number 為空）與「各帳戶期初」，原本查詢只依 `settlement_date DESC` 取一筆，可能取到公司級那筆，導致**每個帳戶都用同一筆公司級期初**，數字錯誤。

**修正**：結算查詢改為 **ORDER BY 優先「同公司＋同帳戶名稱＋同帳號」的結算**，再依 `settlement_date DESC`。  
也就是說：每個銀行帳戶會優先使用「該帳戶自己的期初結算」，沒有時才用公司級結算。

- 受影響 API：`/api/cash-gap-dashboard`、`/api/cash-gap-dashboard-by-dates`

### 2. 交易歸戶：嚴格比對 `account_number`（避免重複計入）

**問題**：同一公司下若有多個「同名帳戶、不同帳號」（例如A公司底下兩個華南帳戶），原本交易條件為  
`(account_number = ? OR account_number IS NULL OR ? IS NULL)`，  
會把 **account_number 為 NULL** 的收支算進**每一個**同名帳戶，造成同一筆支出被重複計入、預計餘額被低估、資金缺口被高估（例如A公司-華南顯示 278959 而非正確的 118534）。

**修正**：改為 **嚴格比對**  
`(account_number = ? OR (account_number IS NULL AND ? IS NULL))`  
- 帳戶有帳號時：只計入「帳號與該帳戶相同」的交易，不計入 `account_number` 為 NULL 的筆數。  
- 帳戶無帳號時：只計入「交易帳號也是 NULL」的筆數。  

因此每筆交易只會歸到一個帳戶，不會重複計入。

- 受影響 API：同上；查詢「未來／過去交易」與「各目標日交易」的 SQL 皆已改為嚴格比對。

## 請您自行確認的項目

### 1. 公司名稱是否一致

資金缺口與交易查詢皆用 **company_name** 比對：

- **公司管理** 裡的名稱（例如：`A公司`）
- **結算記錄** 的「公司名稱」
- **收支記錄（含 Excel 匯入）** 的「公司」欄位

若 Excel 或手動輸入為「A公司」「A公司股份」等，與公司主檔不一致，該筆交易就不會算進該公司的資金缺口。  
**建議**：公司名稱與 Excel 匯入範本中的「公司」欄位完全一致（含全形／半形、空格）。

### 2. 帳戶名稱與帳號

- 銀行帳戶的 **帳戶名稱**、**帳號** 需與 **收支記錄** 的「帳戶／帳號」一致，該帳戶的收支才會被算進該帳戶的餘額與資金缺口。
- 若同一公司下有多個帳戶且**帳戶名稱相同、帳號不同**，請確保每筆收支的「帳戶＋帳號」與要歸屬的銀行帳戶一致，否則可能歸錯戶或漏算。

### 3. 結算記錄的建立方式

- **期初餘額**：若為「各帳戶分別期初」，請在結算時選擇**對應公司＋該帳戶＋該帳號**，系統會依上面邏輯優先使用這筆帳戶級結算。
- 若只建一筆「公司級」期初（不選帳戶），則所有該公司帳戶在「沒有自己的帳戶級結算」時，會共用這筆公司級期初；若您期望的是每戶獨立期初，請改為每個帳戶各建一筆結算。

### 4. Excel 匯入範本欄位對應

匯入時會依**標題列**對應欄位，例如：

- 公司 → `company_name`
- 帳戶／帳戶名稱 → `account_name`
- 帳號 → `account_number`
- 日期、類型、金額等

請確認「收支記錄匯入範本.xlsx」第一列標題與上述對應正確，且**A公司**的資料在「公司」欄位填的是與系統公司主檔一致的名稱（如 `A公司`）。

## 重新匯入後數字仍與 Excel 不符時

系統數字與 Excel 不同，常見原因如下：

1. **期初餘額來源不同**  
   系統的**期初餘額**來自「結算」功能（`balance_settlements`），**不是**來自 Excel。  
   - 若 Excel 裡有某一格的「期初餘額」或「餘額」，請在系統的**結算**裡為該公司＋該帳戶建立一筆結算，且 **actual_balance（實際餘額）與 Excel 的期初一致**。  
   - 若未建立結算或數值不同，則「預計餘額 = 期初 + 收入 - 支出」會與 Excel 不一致。

2. **公司／帳戶／帳號必須完全一致**  
   - 資金缺口只會計入「公司名稱、帳戶名稱、帳號」都與**銀行帳戶**一致的交易。  
   - 匯入範本中的「公司名稱」「帳戶名稱」「帳號」需與「公司管理」「銀行帳戶」完全一致（含全形半形、空格）。  
   - 若同一公司有多個同名帳戶（例如兩個華南、帳號不同），每筆交易必須帶**正確帳號**，否則該筆不會被算進任一帳戶（嚴格比對後不會重複計入，但可能漏計）。

3. **用畫面對帳**  
   - 資金缺口頁每個帳戶現在會顯示：**期初餘額**、**各日的收入合計／支出合計／預計餘額／資金缺口**。  
   - 請對照 Excel：同一日「期初 + 收入 - 支出」是否等於系統的「預計餘額」；若期初不同，請在「結算」建立或修正該帳戶的期初。

4. **對帳 API（可選）**  
   - `GET /api/cash-gap-reconciliation?company=A公司&account=華南` 可回傳該帳戶的期初、各日收入/支出合計與預計餘額，方便與 Excel 逐項比對。

## 若仍有差異可再檢查

1. **資料庫**：查詢 `transactions`、`balance_settlements` 中 `company_name` / `account_name` / `account_number` 實際值，比對是否與「公司管理」「銀行帳戶」一致。
2. **重算餘額**：到「銀行帳戶」頁按「重新計算餘額」，再開「資金缺口」頁（會自動重算）比對。
3. **單一帳戶**：在資金缺口或報表先鎖定「A公司」的**單一帳戶**，手動用「期初＋該戶收支」核對一筆，確認邏輯與資料是否一致。

以上為程式已修正部分與建議您確認的項目；若提供一筆「預期數字 vs 畫面數字」的具體例子，可再對應程式邏輯逐項對。
